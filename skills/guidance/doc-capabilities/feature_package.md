# 能力说明：feature_package（feature-package.md）

> 指南：§3.6.5 / §3.7 / 类型 T-C3（维护索引，供指南更新时同步本文件；AI 无需访问）
> 层级：Level 2（feature）· **精简模式复合** · 位于 `module-<模块名>/features/<功能名>/`

## 定位

精简模式复合功能包：feature_design + decision_log + unit_test + acceptance_test 四合一（4 种均必选）。功能骨架文档——`doc new feature_package --module <名> --feature <功能名>` 创建它时自动建立 `features/<功能名>/` 目录。

## 承载的决议主题

| 决议主题 | 目标章节 |
|---------|---------|
| 功能行为 / 触发 / 边界约束 | ## 功能设计 |
| 设计决策理由与方案对比 | ## 设计决策 |
| 单元测试用例（GWT） | ## 单元测试 |
| 业务验收场景（Gherkin） | ## 验收测试 |

## 段落结构

每个 `##` 章节对应一个基础类型，内部章节与对应基础类型能力文件一致：

- ## 功能设计 → 功能描述 / 触发条件 / 前置条件 / 处理流程 / 异常路径 / 边界约束（同 `feature_design`，含约束编号规则）
- ## 设计决策 → 决策记录（问题/业务Why/技术Why/替代方案/最终决策；**只追加不改写**）
- ## 单元测试 → 测试用例（覆盖约束 + Given/When/Then）
- ## 验收测试 → Gherkin 场景（`# language: zh-CN`）

写作规则与对应基础类型能力文件相同。

## 行文规则

**必须**
- **约束 ID 在整个文档内唯一**（跨章节不重复，因合并后是同一文档）
- `contains` frontmatter 与正文章节保持一致（4 种均必选）
- 拆分（§3.7）时各 `##` 章节成为独立基础文档，版本初始化为 0.1.0

**禁止**
- ❌ 功能包已建后，在精简模式下继续创建功能级独立基础文档（feature_design 等，`doc new` 以 `new_doc.minimal_profile` 拒绝）→ 先拆分或写入本文档
