## 定位

模块间接口**字段级**契约：请求/响应结构、共享事件 payload、共享数据结构。是 AI 生成代码和人工评审的唯一事实依据——接口定义精确到字段级。

## 段落结构（3 个章节）

### §模块间接口定义

每个接口包含：**提供方** / **消费方** / **通信方式**（同步 RPC / 异步消息 / 事件广播）/ **数据格式** + 请求/响应结构（JSON 代码块）+ 约束（[MUST]/[SHOULD] 编号）。

- 正例：请求 `{"order_id": "string (必填)", "items": ["array (扣减条目)"]}`；响应 `{"success": "boolean", "error_code": "int (0=成功, 1=超时, 2=格式错误)", "error_msg": "string"}`；约束 `[MUST] C-101` 超时 ≤ 500ms、`[SHOULD] S-101` 指数退避重试最多 3 次。

### §共享事件定义

每个事件包含：**发布方** / **订阅方**（全部列出）/ **触发条件** + Payload（JSON 代码块）。

- 正例：payload `{"event_id": "string (UUID)", "timestamp": "uint64", "payload": {...}}`。

### §共享数据结构

每个结构包含：**定义归属**（哪个模块负责更新版本）/ **使用范围** + 字段表（字段 | 类型 | 必填 | 说明）。

## 行文规则

**必须**
- 接口定义精确到**字段级**（AI 生成代码的唯一事实依据）
- 能力名称与 `module_manifest` 的 exports/imports 名称**保持一致**（本文档定义「长什么样」，manifest 声明「是否存在、由谁提供」）
- 结构化数据一律用 JSON 代码块（跨模型解析最稳定）
- 判断是否写入：输入/输出结构复杂（3+ 字段或嵌套）、有错误语义、有版本协商/兼容要求、事件被 3+ 模块消费

**禁止**
- ❌ 单个模块的内部接口 → 归模块 `architecture`
- ❌ 能力存在性声明（import/export 配对）→ 归 `module_manifest`
- ❌ 全局架构模式/安全策略 → 归 `global_policies`
- ❌ 简单参数接口（单个 ID/布尔）→ 在 `module_manifest` 描述列注明即可
