# 能力说明：release_policy（release-policy.md）

> 指南：§3.1.2 / 类型 T-15（维护索引，供指南更新时同步本文件；AI 无需访问）
> 层级：Level 0（top）· `module: project-charter` · 推荐 · 编写顺序第 15

## 定位

发布域的权威规则：发布单元划分、发布门禁、发布流水线、发布号规则与回滚策略。门禁与流程的默认定义在指南 §3.8，项目可在本文档中自定义。

## 承载的决议主题

| 决议主题 | 目标章节 |
|---------|---------|
| 发布最小粒度划分 | §发布单元划分 |
| 门禁规则（默认 G1~G6 基础上增删） | §发布门禁 |
| 发布流程阶段划分 | §发布流水线 |
| 发布号规则（建议 YYYY.MM.n） | §发布号规则 |
| 回滚触发条件与机制 | §回滚策略 |

## 段落结构（5 个章节，顺序固定）

- §发布单元划分：默认一个功能（feature 目录下 4 份文档）+ 其 depends_on 依赖链
- §发布门禁：默认门禁 G1 文档健康 / G2 依赖一致 / G3 契约闭合 / G4 约束覆盖 / G5 测试全绿 / G6 实现映射，按需增删
- §发布流水线：默认 P0 变更检测 → P1 静态门禁 → P2 动态门禁 → P3 制品生成 → P4 发布验证 → P5 固化
- §发布号规则：`YYYY.MM.n`，与 Spec 版本（§3.5.7）相互独立
- §回滚策略：定义发布失败时的回滚机制与触发条件

## 行文规则

**必须**
- 门禁在默认 G1~G6 基础上按需增删，删除/新增需注明理由
- 发布号与 Spec 版本独立，避免混淆

**禁止**
- ❌ 部署操作细节 → 归 `technical_framework` §部署模型
- ❌ 某次具体发布的内容 → 发布记录为工具链生成的派生制品，不属于 Spec 文档
