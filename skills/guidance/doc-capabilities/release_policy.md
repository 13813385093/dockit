# 能力说明：release_policy（release-policy.md）

> 指南：§3.1.2 / §3.8 / 类型 T-15（维护索引，供指南更新时同步本文件；AI 无需访问）
> 层级：Level 0（top）· `module: project-charter` · 推荐 · 编写顺序第 15 · 位于 `ProjectSpec/` 根（平铺，不建子目录）

## 定位

发布域的权威规则：发布状态机（draft → in-review → ready → released → superseded）与发布单元划分、发布门禁、发布流水线、发布号规则与回滚策略。门禁与流程的默认定义在指南 §3.8，项目可在本文档中自定义。不写部署操作细节（→ 归 technical_framework §部署模型）与具体发布记录（→ 工具链派生制品）。

## 段落结构（6 个章节，顺序固定）

### §发布状态

发布状态机衡量**可上线度**，与内容生命周期（§3.7）正交——文档可以 active 但尚未通过发布门禁。

- 格式：状态名 + 含义 + 进入条件（列表或表格：状态 | 含义 | 进入条件），取值固定为 5 个状态
- 默认值（指南 §3.8.1）：`draft（草稿）→ in-review（评审中）→ ready（门禁通过）→ released（已发布）→ superseded（被新发布替代）`
- 正例：Spec 变更提交后为 in-review；G1~G6 全绿后置 ready；P5 固化后置 released；被新发布替代记 superseded。
- 反例：跳过 in-review 直接置 released（门禁无记录，回滚时无法定位责任人）。

### §发布单元划分

发布的最小粒度与发布范围的计算方式（层次：项目级，约束全部模块的发布划分）。

- 格式：一段话或列表，给出发布单元的构成规则
- 默认值：一个功能（feature 目录下 4 份文档）+ 其 depends_on 依赖链
- 正例：只改 order 模块 `features/order-timeout-cancel/` 时，发布单元 = 该功能 4 份文档 + 其 depends_on 依赖链。

### §发布门禁

进入 released 前必须通过的校验项与放行规则（层次：项目级，对发布单元内的全部文档生效）。

- 格式：门禁表（门禁 | 校验内容 | 依据机制），沿用 G1~G6 编号，不重新编号
- 默认值：默认门禁 G1 文档健康 / G2 依赖一致 / G3 契约闭合 / G4 约束覆盖 / G5 测试全绿 / G6 实现映射，按需增删
- G4 约束覆盖：校验范围为发布单元内 `feature_design` §边界约束 的编号 [MUST]。
- 正例：小型项目启用 G1/G2/G3/G5 最小门禁；删除 G4 须在本文档注明理由与替代检查。
- 反例：删除 G4 而不注明理由，[MUST] 约束失去覆盖追踪。

### §发布流水线

从变更提交到发布固化的阶段划分（层次：项目级，工具链按此实现）。

- 格式：阶段列表（P0~P5），逐阶段给出校验动作与失败处置
- 默认值：默认 P0 变更检测 → P1 静态门禁 → P2 动态门禁 → P3 制品生成 → P4 发布验证 → P5 固化
- 正例：P1 静态门禁失败即回退到 P0 修复，不进入 P2。

### §发布号规则

发布号的命名规则与递增方式（层次：项目级，与 Spec 版本 §3.5.7 相互独立）。

- 格式：编号模式（如 `YYYY.MM.n`）+ 递增规则
- 默认值：`YYYY.MM.n`，与 Spec 版本（§3.5.7）相互独立
- 正例：2026.03.1（与 Spec 版本 1.4.0 相互独立）。

### §回滚策略

发布失败时的回滚机制与触发条件（层次：项目级，覆盖全部发布单元；指南未规定具体机制，由项目在此定义）。

- 格式：触发条件 + 回滚动作 + 记录要求
- 默认值：定义发布失败时的回滚机制与触发条件
- 正例：P4 冒烟失败 → 回滚到上一个 released 的 release-manifest，并追加一条决策记录。

## 行文规则

> 本节「禁止」＝ 指南 §3.1.2 中本文档的「约束」（写作边界）；指南中的「约束」不指 [MUST]/[SHOULD] 内容级标记。

**必须**
- 落笔格式：六个章节顺序固定；各节先写默认值，再写项目自定义差异
- 编号与命名：门禁沿用 G1~G6、流水线沿用 P0~P5 编号，不重新编号
- 完备性：发布状态取值限定为 draft / in-review / ready / released / superseded；门禁在默认 G1~G6 基础上按需增删，删除/新增需注明理由
- 与他文档的衔接：门禁与状态的取值与指南 §3.8 默认定义对齐，差异在本文档显式声明；发布号与 Spec 版本独立，避免混淆

**禁止**
- ❌ 部署操作细节 → 归 `technical_framework` §部署模型
- ❌ 某次具体发布的内容 → 发布记录为工具链生成的派生制品，不属于 Spec 文档
- ❌ 质量禁忌：模糊表述（「视情况而定」）、不可验证的门禁条件、无来源的规则
