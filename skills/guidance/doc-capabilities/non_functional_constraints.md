# 能力说明：non_functional_constraints（non-functional-constraints.md）

> 指南：§3.1.2 / 类型 T-03（维护索引，供指南更新时同步本文件；AI 无需访问）
> 层级：Level 0（top）· `module: project-charter` · 必选 · 编写顺序第 3

## 定位

不可突破的量化底线：性能、安全、合规、兼容、编码规范指标。每条约束**可验证**——量化指标给数值，规则类给可判定标准。是模块设计与代码评审的判断依据。

## 承载的决议主题

|---------|---------|
| 性能指标（延迟、吞吐、可用性） | §性能约束 |

## 段落结构（5 个章节，顺序固定）

各章节均为约束表（格式：约束 ID | 指标/要求 | 约束值 | 约束级别 | 说明），用 `[MUST]` / `[SHOULD]` 标记级别。

### §性能约束

- 正例：`[MUST] C-101` 通信延迟 ≤ 4ms；`[SHOULD] S-101` 报文重传设置为 3 次；`[MUST] C-102` 系统支持双网口冗余（PRP/HSR）；`[MUST] C-103` 可用性 ≥ 99.99%。

### §安全约束

- 正例：`[MUST] C-201` 认证支持 OAuth2；`[MUST] C-202` 传输使用 TLS 1.3；`[MUST] C-203` 遵循 MISRA C 安全编码规范；`[MUST] C-204` 符合 IEC 62304 医疗软件标准。

### §编码规范

- 正例：`[MUST] C-301` 代码遵循团队编码规范（ESLint 规则集）；`[SHOULD] S-301` 提交前运行静态检查。

### §平台兼容性

- 正例：`[MUST] C-401` 兼容 Windows 10+ / macOS 12+ / Ubuntu 20.04+；`[SHOULD] S-401` 支持 Chrome 和 Firefox 最新两个大版本。

### §第三方依赖约束

- 正例：`[MUST] C-501` 依赖版本锁定（锁文件提交仓库）；`[SHOULD] S-501` 依赖漏洞扫描每周执行。

## 行文规则

**必须**
- 编号规则：`[MUST]` 必须编号 `C-1xx`；`[SHOULD]` 建议编号 `S-1xx`；`[MAY]` 不编号；ID 文档内唯一，修改内容保留 ID，删除则 ID 废弃不复用
- 每条约束可验证：量化指标直接给数值，规则类给出可判定标准
- 与 `global_policies` 的分工：本文档回答「必须达到什么指标」，`global_policies` 回答「全局方案怎么选、怎么做」

**禁止**
- ❌ 理想目标或愿景（如「希望系统性能卓越」）→ 不可验证的不写
- ❌ 技术选型声明 → 归 `technical_framework`
- ❌ 跨模块方案（认证方式、日志格式）→ 归 `global_policies`
- ❌ 功能级约束（功能特有指标）→ 归 `feature_design` §边界约束
