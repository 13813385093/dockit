# 能力说明：non_functional_constraints（non-functional-constraints.md）

> 指南：§3.1.2 / 类型 T-03（维护索引，供指南更新时同步本文件；AI 无需访问）
> 层级：Level 0（top）· `module: project-charter` · 必选 · 编写顺序第 3 · 位于 `ProjectSpec/` 根（平铺，不建子目录）

## 定位

不可突破的量化底线：性能、安全、合规、兼容、编码规范指标。每条约束**可验证**——量化指标给数值，规则类给可判定标准。是模块设计与代码评审的判断依据。不写不可验证的目标（→ 删除而非改归属）。

## 承载的决议主题

| 决议主题 | 落点（章节 / 新增记录） |
|---------|---------|
| 性能指标（延迟、吞吐、可用性） | §性能约束 |
| 安全与合规要求（认证、加密、行业标准） | §安全约束 |
| 编码规范强制项 | §编码规范 |
| 平台/浏览器/硬件兼容范围 | §平台兼容性 |
| 第三方依赖管理要求 | §第三方依赖约束 |

## 段落结构（5 个章节，顺序固定）

各章节均为**约束表**，统一表头 `| 约束 ID | 指标/要求 | 约束值 | 约束级别 | 说明 |`；维度不同的章节可按维度调整列名（如 §平台兼容性 用 `| 约束 ID | 维度 | 约束级别 | 目标平台/版本 |`、§第三方依赖约束 用 `| 约束 ID | 依赖约束 | 约束级别 | 说明 |`）。级别标记见 [`[MUST]`/`[SHOULD]`](指南 §3.5.5)。

### §性能约束

性能底线的量化条目——项目级门槛，所有模块与功能均不得突破。

- 格式：表格，表头 `| 约束 ID | 指标/要求 | 约束值 | 约束级别 | 说明 |`
- 正例：

| 约束 ID | 指标/要求 | 约束值 | 约束级别 | 说明 |
|---------|----------|--------|---------|------|
| C-101 | 通信延迟 | ≤ 4ms | [MUST] | 采样值上报链路 |
| S-101 | 报文重传次数 | 3 次 | [SHOULD] | 丢包场景 |
| C-102 | 双网口冗余 | 支持 PRP/HSR | [MUST] | 网络可靠性 |
| C-103 | 可用性 | ≥ 99.99% | [MUST] | 保护类功能 |

### §安全约束

本文档只写**必须达到的门槛与符合性要求**（须支持 OAuth2、须 TLS 1.3、须符合 IEC 62304）；**认证/加密/合规的实施方案与落地机制归 `global_policies.md` §安全与认证、§合规与审计**。

- 格式：表格，表头 `| 约束 ID | 要求 | 约束级别 | 说明 |`
- 正例：

| 约束 ID | 要求 | 约束级别 | 说明 |
|---------|------|---------|------|
| C-201 | 认证支持 OAuth2 | [MUST] | 统一认证入口 |
| C-202 | 传输使用 TLS 1.3 | [MUST] | 通信加密 |
| C-203 | 遵循 MISRA C 安全编码规范 | [MUST] | 行业标准符合性 |
| C-204 | 符合 IEC 62304 医疗软件标准 | [MUST] | 行业标准符合性 |

### §编码规范

本文档只声明**强制级别与可验证门槛**（如覆盖率 ≥ 80%、遵循 ESLint 规则集）及其编号；**规范的具体内容与工具链约定归 `global_policies.md` §代码规范**。

- 格式：表格，表头 `| 约束 ID | 规范要求 | 约束级别 | 说明 |`
- 正例：

| 约束 ID | 规范要求 | 约束级别 | 说明 |
|---------|---------|---------|------|
| C-301 | 代码遵循团队编码规范（ESLint 规则集） | [MUST] | 强制门槛 |
| C-302 | 单元测试覆盖率 | ≥ 80% | [MUST] | 覆盖率是门槛，规范内容归 `global_policies` §代码规范 |
| S-301 | 提交前运行静态检查 | [SHOULD] | 提交前置检查 |

### §平台兼容性

必须支持的平台/浏览器/硬件范围——验收与测试环境的覆盖边界。

- 格式：表格，表头 `| 约束 ID | 维度 | 约束级别 | 目标平台/版本 |`
- 正例：

| 约束 ID | 维度 | 约束级别 | 目标平台/版本 |
|---------|------|---------|-------------|
| C-401 | 操作系统 | [MUST] | Windows 10+ / macOS 12+ / Ubuntu 20.04+ |
| S-401 | 浏览器 | [SHOULD] | Chrome 和 Firefox 最新两个大版本 |

### §第三方依赖约束

第三方依赖的准入与维护门槛（版本锁定、漏洞扫描、许可证）。

- 格式：表格，表头 `| 约束 ID | 依赖约束 | 约束级别 | 说明 |`
- 正例：

| 约束 ID | 依赖约束 | 约束级别 | 说明 |
|---------|---------|---------|------|
| C-501 | 依赖版本锁定（锁文件提交仓库） | [MUST] | 构建可复现 |
| S-501 | 依赖漏洞扫描每周执行 | [SHOULD] | 安全审计 |

## 行文规则

> 本节「禁止」＝ 指南 §3.1.2 中本文档的「约束」（写作边界）；指南中的「约束」不指 [MUST]/[SHOULD] 内容级标记。

**必须**
- 落笔格式：各章节均为约束表，一条约束一行；编号区间按 §性能约束 C-1xx / §安全约束 C-2xx / §编码规范 C-3xx / §平台兼容性 C-4xx / §第三方依赖约束 C-5xx 分带
- 编号与命名：`[MUST]` 必须编号 `C-1xx`；`[SHOULD]` 建议编号 `S-1xx`；`[MAY]` 不编号；ID 文档内唯一，修改内容保留 ID，删除则 ID 废弃不复用。编号在**本文档内唯一**；跨文档引用用完整形式（语法见指南 §3.5.5）：`<doc_type>@project-charter:C-101`（顶层）／`<doc_type>@<模块名>:C-101`（模块层）／`<doc_type>@<模块名>.<功能名>:C-101`（功能层）。
- 完备性：每条约束可验证——量化指标直接给数值，规则类给出可判定标准
- 与他文档的衔接：与 `global_policies` 的分工：本文档回答「必须达到什么指标」，`global_policies` 回答「全局方案怎么选、怎么做」

**禁止**
- ❌ 理想目标或愿景（如「希望系统性能卓越」）→ 不可验证的不写
- ❌ 技术选型声明 → 归 `technical_framework`
- ❌ 跨模块方案（认证方式、日志格式）→ 归 `global_policies`
- ❌ 功能级约束（功能特有指标）→ 归 `feature_design` §边界约束
- ❌ 编码规范的具体内容（格式化/类型检查/语言版本）→ `global_policies` §代码规范
- ❌ 认证/加密/审计的具体实现方案 → `global_policies`
- ❌ 质量禁忌：模糊表述（「较快」「尽量」）、不可验证的门槛、无来源的指标
