# 能力说明：architecture（architecture.md）

> 指南：§3.2.2 / 类型 T-07（维护索引，供指南更新时同步本文件；AI 无需访问）
> 层级：Level 1（module）· 必选 · 编写顺序第 7 · 位于 `module-<模块名>/`

## 定位

模块的整体架构：组件划分、职责、组件间关系与关键流程（HOW 的实现蓝图）。阅读者通过本文档理解模块负责什么、不负责什么、如何与其他模块交互（跨模块的能力依赖与字段级契约分别见 module_manifest / inter_module_contract）。

## 段落结构（5 个章节，顺序固定）

### §模块概述

描述本模块核心职责和在系统中的定位。

- 格式：一段文字（1~3 句）
- 正例：IEC 61850 接入网关模块，负责实现电力设备的标准通信接入，对上对接调度系统，对下管理各逆变器设备。

### §核心能力

列出本模块提供的关键能力。

- 格式：要点列表（每条一句能力描述）
- 正例：SV 采样值接收与解析；GOOSE 报文收发；MMS 远程控制。

### §组件划分

表格列出内部组件。

- 格式：组件 | 职责 | 依赖的内部组件
- 正例：协议适配层（负责 IEC 61850 协议编解码）；业务逻辑层（保护逻辑、控制逻辑）；数据持久层（采样值存储、事件记录）。

### §模块接口

分**对外接口**（本模块提供给其他模块）与**对内接口**（组件间约定）两张表，**不重复字段细节**。接口只列**能力名 + 用途 + 约束**；**签名归 `module_manifest.md` §Exports**，字段级请求/响应与错误码归 `inter-module-contracts.md`。

- 格式：对外接口（能力名 | 用途 | 约束）；对内接口（调用方 | 被调方 | 能力名）
- 正例：对外接口 `receive_sv_data(stream_id, dataset) → (status, parsed_data)`，约束 `[MUST] C-701` 延迟 ≤ 1ms。
- 正例：对内接口 协议适配层 → 业务逻辑层：`on_sv_sample(sample)`；业务逻辑层 → 数据持久层：`save_sample(sample)`。

### §关键流程

有序步骤描述关键业务流程。本节的流程是**模块/组件级**编排；**单个功能从触发到完成的行为链归 `feature_design.md` §处理流程**。Mermaid 流程图（可选）需**同时附文字流程描述**作为兜底。

- 格式：有序步骤列表（每步一句，可用 → 串联）；可附 Mermaid 流程图，但须同时给文字流程描述
- 正例：SV 模块接收采样值 → 保护逻辑计算电压偏差 → 判断是否超过阈值 → 生成 GOOSE 跳闸报文 → 发送至智能终端。

## 行文规则

> 本节「禁止」＝ 指南 §3.2.2 中本文档的「约束」（写作边界）；指南中的「约束」不指 [MUST]/[SHOULD] 内容级标记。

**必须**
- 落笔格式：按 §段落结构 的 5 个章节顺序落笔；每节先写一句话说明，再给格式与正例
- 编号与命名：接口约束按 §3.5.5 编号：`[MUST]` 用 `C-`、`[SHOULD]` 用 `S-`。编号在**本文档内唯一**；跨文档引用用完整形式（语法见指南 §3.5.5）：`<doc_type>@project-charter:C-101`（顶层）／`<doc_type>@<模块名>:C-101`（模块层）／`<doc_type>@<模块名>.<功能名>:C-101`（功能层）。
- 完备性：§模块概述 / §核心能力 / §组件划分 / §模块接口 / §关键流程 缺一不可；每条 [MUST] 约束须可验证（给出量化阈值或明确判定条件），并落在具体接口或流程步骤上
- 与他文档的衔接：接口只列能力名与用途；领域实体 → `domain_model`，能力存在性声明 → `module_manifest` §Exports，字段级契约 → `inter_module_contract`，外部集成 → `integration`
- Mermaid 流程图必须附文字兜底（不同模型渲染支持有差异）

**禁止**
- ❌ 逐行代码实现 → 源码文件
- ❌ 领域实体定义 → 归 `domain_model`
- ❌ 能力存在性声明（import/export 配对）→ 归 `module_manifest`
- ❌ 字段级契约（请求/响应结构、错误码）→ 归 `inter_module_contract`
- ❌ 接口签名（签名 → `module_manifest` §Exports）
- ❌ 单功能行为规格（触发条件 / 处理流程 / 边界约束）→ `feature_design`
- ❌ 外部系统集成细节 → 归 `integration`
- ❌ 质量禁忌：模糊表述（「架构清晰」「性能要好」）、不可验证的约束、无来源的组件划分
