## 定位

领域实体、值对象、聚合根及其业务不变条件（DDD 战术设计产出物）。每个聚合根、实体、值对象都有明确的责任边界。不写数据库表结构与 ORM 映射（→ 源码）、模块接口（→ architecture）。

## 段落结构（4 个章节，顺序固定）

> 本文档正文即指南 §3.2.2 的「领域模型定义」：按类型分 4 个固定章节，每个领域对象统一模板（**类型** / **属性** / **行为** / **约束**）。

### §聚合根

领域模型入口，通过 ID 引用，保证聚合内一致性。

- 格式：**类型** / **属性** / **行为** / **约束**
- 正例：MMXU 测量单元（聚合根）：属性 AnIn1 电压值 (float)、AnIn2 电流值 (float)、Hz 频率值 (float)；行为：超限告警（电压/电流超过阈值时触发）、数据同步（支持 IEEE 1588 协议同步）。

### §实体

有唯一标识，生命周期内状态可变。

- 格式：**类型** / **属性** / **行为** / **约束**
- 正例：CSWI 开关控制（实体）：属性 Pos$stVal 开关位置状态 (boolean)、Pos$ctlVal 开关控制命令 (boolean)；约束：遥控操作必须通过双重身份认证。

### §值对象

无唯一标识，通过属性值判断相等性，不可变。

- 格式：**类型** / **属性** / **行为** / **约束**
- 正例：Coordinate 坐标（值对象）：属性 x/y/z (double)。

### §领域约束

跨实体的全局业务规则表。本节只收**跨实体**的不变条件；**单实体/单值对象**的规则写在该对象自己的「约束」要素内。

- 格式：约束 ID | 规则 | 约束级别 | 涉及实体
- 正例：

| 约束 ID | 规则 | 约束级别 | 涉及实体 |
|---------|------|---------|---------|
| C-801 | 遥控操作必须通过双重身份认证 | [MUST] | CSWI |
| C-802 | 电压采样值不得超过额定值的 120% | [MUST] | MMXU |

## 行文规则

> 本节「禁止」＝ 指南 §3.2.2 中本文档的「约束」（写作边界）；指南中的「约束」不指 [MUST]/[SHOULD] 内容级标记。

**必须**
- 落笔格式：每个领域对象按统一模板落笔（**类型** / **属性** / **行为** / **约束**），并按 4 个固定章节归类
- 编号与命名：业务规则用 `[MUST]` / `[SHOULD]` 标记并编号。编号在**本文档内唯一**；跨文档引用用完整形式（语法见指南 §3.5.5）：`<doc_type>@project-charter:C-101`（顶层）／`<doc_type>@<模块名>:C-101`（模块层）／`<doc_type>@<模块名>.<功能名>:C-101`（功能层）。
- 完备性：每个领域对象标注**类型**（聚合根 / 实体 / 值对象）；每条约束须可验证（可判定真假的业务不变条件），并写清落在哪个领域对象或属跨实体规则
- 行为描述业务逻辑，而非技术实现
- 与他文档的衔接：术语的业务定义 → `business_context`，模块接口 → `architecture`，功能行为与边界约束 → `feature_design`

**禁止**
- ❌ 数据库表结构或 ORM 映射（实现细节）→ 源码
- ❌ 模块接口定义 → 归 `architecture`
- ❌ 功能行为与边界约束 → 归 `feature_design`
- ❌ 质量禁忌：模糊表述（「数据尽量准确」）、不可验证的规则、无来源的约束
