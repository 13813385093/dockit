## 定位

领域实体、值对象、聚合根及其业务不变条件（DDD 战术设计产出物）。每个聚合根、实体、值对象都有明确的责任边界。

## 段落结构（4 个章节，顺序固定）

每个领域概念统一模板：**类型** / **属性** / **行为** / **约束**。

### §聚合根

领域模型入口，通过 ID 引用，保证聚合内一致性。

- 正例：MMXU 测量单元（聚合根）：属性 AnIn1 电压值 (float)、AnIn2 电流值 (float)、Hz 频率值 (float)；行为：超限告警（电压/电流超过阈值时触发）、数据同步（支持 IEEE 1588 协议同步）。

### §实体

有唯一标识，生命周期内状态可变。

- 正例：CSWI 开关控制（实体）：属性 Pos$stVal 开关位置状态 (boolean)、Pos$ctlVal 开关控制命令 (boolean)；约束：遥控操作必须通过双重身份认证。

### §值对象

无唯一标识，通过属性值判断相等性，不可变。

- 正例：Coordinate 坐标（值对象）：属性 x/y/z (double)。

### §领域约束

跨实体的全局业务规则表（格式：约束 ID | 规则 | 约束级别 | 涉及实体）。

- 正例：`[MUST] C-1xx` 遥控操作必须通过双重身份认证；`[MUST] C-1xx` 电压采样值不得超过额定值的 120%。

## 行文规则

**必须**
- 每个领域对象标注**类型**（聚合根 / 实体 / 值对象）
- 业务规则用 `[MUST]` / `[SHOULD]` 标记并编号（文档内唯一）
- 行为描述业务逻辑，而非技术实现

**禁止**
- ❌ 数据库表结构或 ORM 映射（实现细节）→ 源码
- ❌ 模块接口定义 → 归 `architecture`
- ❌ 功能行为与边界约束 → 归 `feature_design`
