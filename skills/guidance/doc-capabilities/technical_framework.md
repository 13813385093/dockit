# 能力说明：technical_framework（technical-framework.md）

> 指南：§3.1.2 / 类型 T-02（维护索引，供指南更新时同步本文件；AI 无需访问）
> 层级：Level 0（top）· `module: project-charter` · 必选 · 编写顺序第 2 · 位于 `ProjectSpec/` 根（平铺，不建子目录）

## 定位

全局技术选型与架构风格：语言、框架、中间件、部署、工具链。只记录**最终选型及其理由**，不罗列候选（候选对比 → 归 `decision_log`）。所有模块的技术决策均应在此框架内做出。

## 承载的决议主题

| 决议主题 | 落点（章节 / 新增记录） |
|---------|---------|
| 语言/运行时、数据存储、通信协议选型 | §技术栈概览 |
| 整体架构风格（分层/微服务/事件驱动/模块化单体） | §架构风格 |
| 关键框架与中间件选型 | §主要框架与中间件 |
| 部署形态与运行环境 | §部署模型 |
| 开发工具与 CI 约定 | §开发环境与工具链 |

## 段落结构（5 个章节，顺序固定）

### §技术栈概览

表格列出核心选型。

- 格式：技术类别 | 技术 | 版本 | 选型理由 | 约束/规模预估
- 正例：语言与运行时 → Python 3.11+（AI 生态丰富，团队技术栈统一）；数据存储 → PostgreSQL（结构化数据，ACID 事务要求）；通信协议 → MQTT（物联网设备通信）。

### §架构风格

描述整体架构风格及选型理由。

- 格式：一段话，给出风格名称 + 选型理由
- 正例：事件驱动 + 模块化单体：业务模块边界清晰，事件解耦跨模块协作。

### §主要框架与中间件

表格列出框架/中间件。

- 格式：框架/中间件 | 版本 | 用途 | 备选方案
- 正例：FastAPI（轻量 async，自动生成 OpenAPI 文档）；RabbitMQ（可靠消息投递，支持延时队列）。

### §部署模型

描述部署形态与运行环境。

- 格式：一段话，说明部署形态（容器化 / 边缘-云两级等）与运行环境
- 正例：容器化部署（Docker + Kubernetes），按模块水平扩展；边缘节点 + 云端两级部署。

### §开发环境与工具链

描述开发环境与工具链约定。

- 格式：列表，逐项给出工具与其约定（IDE / CI 等）
- 正例：IDE：VS Code + Python 插件；CI：GitHub Actions，提交即构建。

## 行文规则

> 本节「禁止」＝ 指南 §3.1.2 中本文档的「约束」（写作边界）；指南中的「约束」不指 [MUST]/[SHOULD] 内容级标记。

**必须**
- 落笔格式：每个选型附选型理由（技术栈概览表「选型理由」列必填）
- 编号与命名：技术名称与版本号用官方写法（如 `PostgreSQL 16`），全文统一，不混用简称与全称
- 完备性：涉及规模预估/约束时给出量级（如数据规模 <10TB）
- 与他文档的衔接：跨模块的通信约定（消息命名、幂等语义、重试死信）与系统级异常/一致性策略归 `global_policies`，本文档只定风格与选型。

**禁止**
- ❌ 罗列所有候选技术（只记最终选型）→ 候选对比归 `decision_log`
- ❌ 单个模块的内部技术细节 → 归对应模块 `architecture`
- ❌ 量化性能/安全指标底线 → 归 `non_functional_constraints`
- ❌ 跨模块技术策略（认证、日志等）→ 归 `global_policies`
- ❌ 质量禁忌：模糊表述（「主流技术」「高性能」）、不可验证的选型理由、无来源的结论
